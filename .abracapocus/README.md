# SHREDBOOST_1_0

## Purpose

Build ShredBoost 1.0: an aggressive pre-amp attack shaper, overdrive, and low-end tightener engineered for high-gain thrash rhythm and fast lead guitar, as a complete professional C++20 JUCE plugin. Product identity (binding, used consistently in CMake, plugin metadata, and state): project/plugin name ShredBoost, vendor nSpace Systems, version 1.0.0, manufacturer code NSPC, plugin code ShBs, bundle identifier com.nspacesystems.shredboost, LV2 URI urn:nspacesystems:plugin:shredboost. Target formats: Linux VST3, Linux LV2, Linux Standalone; a windows-msvc CMake preset is generated as configuration for later Windows tooling. JUCE is a git submodule at ./JUCE pinned to commit 7c9d3783b127263d72bb65fe0a7e2dc8a02a7ac2; no task modifies anything under JUCE/. Binding engineering rules restated into materialized tasks: (1) Real-time constraints: inside processBlock zero heap allocation, locks, file IO, string construction, GUI calls, or buffer resizing; all buffers allocated during prepareToPlay; juce::ScopedNoDenormals instantiated at top of processBlock. (2) Domain smoothing: linear SmoothedValue for dB values (input_trim, mid_amount, drive, level, pick_attack); multiplicative SmoothedValue for strictly positive frequencies (tight_cut, mid_freq, tone); 15 ms equal-power crossfade for discrete topology switches (voicing_mode). (3) DSP processing chain order: [0] Input Trim -> [1] Pre-Drive Tight HPF (RBJ 2nd-order, Q=0.707 or Q=1.2 Precision Tight) -> [2] Pre-Clip Mid Voicing Bell (RBJ 2nd-order) -> [3] Level-Independent Transient Pick-Attack Shaper -> [4] Oversampling Upsample (1x/2x/4x polyphase FIR) -> [5] Nonlinear Clip (Yng-Grey, Precision Tight, SD-1, Clean) -> [6] Downsample + Anti-Aliasing LPF -> [7] DC Blocker (1st-order HPF, R=0.9975) -> [8] Post-Drive Tone LPF -> [9] Output Level + Gain-Matched Bypass RMS Tracker. (4) Oversampling changes happen on the message thread with re-prepare and a 10 ms mute-fade, reporting PDC latency via setLatencySamples. (5) Testing uses the juce::UnitTest console runner target executed via CTest; no third-party testing frameworks allowed. (6) Explicit cmake/ctest verification commands are required per task as no C++ language adapter exists in the registry.
